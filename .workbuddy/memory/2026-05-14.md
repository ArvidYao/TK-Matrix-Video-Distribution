## 11:48 - 传输引擎迁移：pymobiledevice3 → afcclient (libimobiledevice)

### 背景
- 用户反馈 pymobiledevice3 非常不稳定，今天分发全部失败
- 用户希望使用爱思助手(i4Tools/i4)的通道，因为手动传输也用爱思

### 调研结论
- **爱思助手没有 CLI/AppleScript/自动化接口**，纯 GUI 应用，无法编程调用
- 但爱思底层也是用 **libimobiledevice 的 AFC 协议**（和 `afcclient` 同源）
- 系统已安装 libimobiledate 工具链：`afcclient`, `idevice_id`, `ideviceinfo`
- **方案：切换到 afcclient 命令行工具作为主力传输引擎**

### 代码改动 (tk_distributor_core.py - FileTransfer 类)
1. **`_upload_cli()`** — 从 `python -m pymobiledevice3 afc push` 改为 `afcclient put` (C 原生实现)
2. **`_query_existing_files()`** — 从 `pymobiledevice3 afc ls` 改为 `afcclient ls` (pipe 模式)
3. 方案2备用仍保留 pymobiledevice3 async AFC API 作为 fallback
4. Photos.sqlite 重建操作保持不变（通知类操作不影响稳定性）

### 测试结果
- ✅ afcclient 连接设备正常，可列文件/上传/删除
- ✅ Dry-run 完整流程通过
- ✅ **真实上传测试：53MB 视频，0.4 秒完成**（速度极快）
- ✅ Web 服务正常启动，API 状态正确
- ✅ 照片库重建后台线程正常启动

### 关键优势
- afcclient 是 C 语言实现，不依赖 Python asyncio 线程模型
- 与爱思助手同源协议栈，稳定性经过多年验证
- 不存在 pymobiledevice3 的 USB 连接竞争问题

### 背景

- **用户要求改为桌面应用**（不用网页），PyQt6 已安装 (v6.11.0)

### 实施内容
1. **新建 `tk_distributor_app.py`** — PyQt6 桌面应用主程序
   - MainWindow: 设备列表 + 视频目录选择 + 日志 + 进度条 + 操作按钮
   - DistributeWorker(QThread): 后台线程，复用 DeviceManager/VideoAllocator/ImportController
   - 信号机制: log, progress, device_start, device_done, finished, error
   - **完成弹删除确认对话框**: QMessageBox.question 询问是否删除已导入视频
   - 运行时显示警告横幅 "⚠️ 正在操控爱思助手请勿操作鼠标键盘"
2. **改造 `i4tools_remote.py`**
   - `ImportController.__init__()` 新增 `progress_callback` 参数
   - 新增 `_report()` 回调方法
   - 新增 `step_select_device(device_name)` 方法 — 多设备切换（点击设备下拉框 → 输入设备名前3字匹配 → 回车）
   - `import_video()` 签名变为 `(video_path, device_name=None) -> dict`
   - 返回值从 `bool` 改为 `{"success", "duration", "error"}`
   - 动态构建步骤列表：有 device_name 时插入设备切换步骤

### 技术细节
- PyQt6 枚举必须用完整路径: `QTextCursor.MoveOperation.End`, `Qt.AlignmentFlag.AlignCenter`, `QFileDialog.Option.ShowDirsOnly`, `Qt.CursorShape.PointingHandCursor`
- macOS 字体: Consolas 不存在，需后续替换为 Menlo/Monaco
- pyautogui 和 PyQt6 可以共存无冲突
- ImportController 使用延迟动态导入 (`from i4tools_remote import ...`) 放在 WorkerThread.run() 内部
