## 第二轮修复（19:46~20:00）

### 问题1：传到 DCIM/100APPLE 后照片 App 仍看不到
- **根因**：AFC 直接写入的文件 iOS 照片库不会自动索引，需要触发 MediaScanner
- **修复**：新增 `trigger_photo_library_rescan()` 方法，上传完成后通过 `NotificationProxyService` 发送 3 个 iOS 系统通知：
  - `com.apple.mobile.assetsd.assetUpdated`
  - `com.apple.MobileAssetManager.ScanComplete`
  - `_MCSettings.ConfiguredAccountsChanged`
- 已手动发送通知到设备，需用户确认照片 App 是否能看到

### 问题2：重置按钮失效
- API 测试完全正常（curl 返回 success: true，清除了 12 个视频 + 5 条历史）
- **可能原因**：confirm 对话框被忽略或网络问题
- **改进**：
  - confirm 文案更详细醒目
  - 按钮加 loading 状态防止重复点击
  - 取消时也显示 toast 提示
  - 重置后自动刷新历史页面

### 问题3：取消勾选自动删除但视频仍被删
- **根因**：`run_distribution_task` 用 `state.get_config_copy()` 读内存缓存，用户改设置后如果没重启服务或没点保存就用旧值
- **修复**：改为每次启动分发任务时直接从 config.yaml 文件 `load_config()` 实时读取
- 同时把默认值 `auto_delete_after_upload` 从 `true` 改为 `false`（更安全）

## 2026-05-14 补充：纯命令行 iPhone 导入工具

### 新建 import_to_iphone.py
- **基于 PyMobileDevice3 AFC 服务**，无需 GUI、无需爱思助手
- **功能**：通过 USB 直接推送媒体文件到 iPhone DCIM/100APPLE
- **自动触发照片库刷新**：通过 NotificationProxyService 发送 3 个系统通知
  - com.apple.photos.PhotoLibraryChangeObserver
  - com.apple.mobile.assetd  
  - com.apple.photos.ImageCapture
- **速度**：USB 2.0 约 28-30 MB/s（157.5MB 文件 ~5 秒）
- **用法**：`python3 import_to_iphone.py <文件或文件夹路径>`
- **优势**：不怕鼠标干扰，可批量处理，可集成到自动化流程

### 技术要点
- 使用 `create_using_usbmux()` 创建连接（与 CLI 工具一致的方式）
- MuxDevice 属性：serial, is_usb, is_network, devid（注意不是 device_name/product_type 等）
- AFC 推送到 DCIM/100APPLE 目录才能被照片 App 识别
- PyMobileDevice3 v9.12.0 API 变化较多，需要用 inspect 查源码确认正确用法
